Biome 最好作为你项目的开发依赖来安装，但它也可以作为[独立可执行文件]使用，后者无需 Node.js。

[独立可执行文件]: /guides/manual-installation

<PackageManagerCommand
  npm={["i -D -E @biomejs/biome"]}
  pnpm={["add -D -E @biomejs/biome"]}
  yarn={["add -D -E @biomejs/biome"]}
  bun={["add -D -E @biomejs/biome"]}
  deno={["add -D npm:@biomejs/biome"]}
/>

<Aside type="note" title="版本锁定">

`-E` 确保包管理器锁定 Biome 的版本。更多有关[为什么锁定版本很重要]的信息，
请参阅[版本管理页面](/internals/versioning)。

</Aside>

[为什么锁定版本很重要]: /internals/versioning#why-pinning-the-version-is-important

## 配置

尽管 Biome 可以在零配置下运行，但你多半会想调整一些设置以满足项目的需要。
这种情况下，你可以运行以下命令来生成一个 `biome.json` 配置文件。

## 用法

我们来快速了解一下如何在你的项目中使用 Biome。

### 命令行接口（CLI）

Biome 提供了一个[命令行接口]，用于格式化、Lint 和检查你的代码。

[命令行接口]: /reference/cli

<Tabs syncKey="command">
	<TabItem label="npm" icon="seti:npm">
		

```bash
# 格式化所有文件
npx @biomejs/biome format --write

# 格式化指定文件
npx @biomejs/biome format --write <files>

# 对所有文件执行 Lint 并应用安全修复
npx @biomejs/biome lint --write

# 对指定文件执行 Lint 并应用安全修复
npx @biomejs/biome lint --write <files>

# 对所有文件执行格式化、Lint 并整理导入
npx @biomejs/biome check --write

# 对指定文件执行格式化、Lint 并整理导入
npx @biomejs/biome check --write <files>
```

### 编辑器集成

Biome 在你喜爱的编辑器中提供第一方扩展。

- [VS Code](/editors/first-party-extensions#vs-code)
- [IntelliJ](/editors/first-party-extensions#intellij)
- [Zed](/editors/first-party-extensions#zed)

对于其他编辑器，还有[社区扩展](/editors/third-party-extensions)，
例如 **Vim**、**Neovim** 和 **Sublime Text** 等。

### 持续集成（CI）

在你的 CI 流水线中运行 `biome ci`，以在整个团队中强制保证代码质量与一致性。
它的用法与 `biome check` 命令相同，但针对 CI 环境做了优化。

- [GitHub Actions](/recipes/continuous-integration#github-actions)
- [GitLab CI](/recipes/continuous-integration#gitlab-ci)

更多示例请参阅[持续集成](/recipes/continuous-integration)配方。
