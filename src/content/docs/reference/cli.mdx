通过命令行接口（CLI），你可以在终端或持续集成（CI）环境中检查、格式化、Lint 和管理 Biome。

Biome CLI 既可以通过项目的包管理器运行，也可以作为不依赖 Node.js 的[独立原生可执行文件](/guides/manual-installation)运行。

<Tabs syncKey="cli-command">

	</TabItem>
	<TabItem label="pnpm" icon="pnpm">

	</TabItem>

	</TabItem>

		```shell
		biome check .
		```
	</TabItem>

运行 `biome --help` 可列出所有可用命令，也可以在命令后添加 `--help` 查看其用法、参数和选项（例如 `biome check --help`）。

</Aside>

## `biome version`

打印 Biome CLI 的版本号以及所连接的守护进程服务器信息（若有），然后退出。

该命令还接受[全局选项](#global-flags)。

## `biome upgrade`

将 Biome 升级到最新稳定版本。

该命令会根据当前的安装方式升级 Biome 二进制文件：

- **Standalone**：就地升级独立二进制文件到最新稳定版本。
- **Homebrew**：如果 Biome 是通过 Homebrew 安装的，该命令会运行 `brew upgrade biome`。

将 `BIOME_DISTRIBUTION` 设置为 `npm`、`homebrew` 或 `standalone` 可以覆盖自动检测。

<Aside type="note">

该命令无法更新通过 npm 安装的 Biome 二进制文件。请改用你的包管理器更新 `@biomejs/biome`。

</Aside>

## `biome rage`

打印故障排查报告，包含 CLI、平台、环境、配置、工作区以及守护进程服务器的信息。

该命令还接受[全局选项](#global-flags)、相关的[共享选项](#shared-flags)，以及以下附加选项：

<h3>选项</h3>

#### `--daemon-logs`

在报告中包含最新的守护进程日志。如果 CLI 未连接到守护进程服务器，该选项还会探测正在运行的 Biome 守护进程实例。

#### `--formatter`

包含从 Biome 配置加载的格式化器设置。

#### `--linter`

包含从 Biome 配置加载的 Linter 设置和已启用的 Lint 规则。

## `biome start`

启动 Biome 守护进程服务器，用于与第三方客户端（如编辑器扩展）集成。

该命令还接受相关的[共享选项](#shared-flags)。

## `biome stop`

如果 Biome 守护进程服务器正在运行，则将其停止。

## `biome check`

对指定文件执行格式化、Lint 和 Assist 辅助操作检查。

可选的 `PATH` 参数接受一个或多个文件或目录路径。若省略，Biome 会检查当前工作目录中的文件。

```shell
biome check ./src
```

该命令还接受[全局选项](#global-flags)、相关的[共享选项](#shared-flags)，以及以下附加选项：

<h3>选项</h3>

#### `--write`, `--fix`

应用格式化更改、安全 Lint 修复和安全 Assist 辅助操作。

#### `--unsafe`

允许 `--write` 或 `--fix` 应用不安全修复及 Assist 辅助操作。

#### `--formatter-enabled=<true|false>`

为当前命令启用或禁用格式化检查。

```shell
biome check --formatter-enabled=false
```

#### `--linter-enabled=<true|false>`

为当前命令启用或禁用 Lint 检查。

```shell
biome check --linter-enabled=true
```

#### `--assist-enabled=<true|false>`

为当前命令启用或禁用 Assist 辅助操作。

```shell
biome check --assist-enabled=true
```

#### `--enforce-assist=<true|false>`

强制执行 Assist 辅助操作，若必需的操作未被应用，命令将失败。默认为 `true`。

```shell
biome check --enforce-assist=false
```

#### `--profile-rules`

报告每条规则的运行耗时。不包括准备分析所花费的时间，例如构建语义模型的时间。

#### `--stdin-file-path=PATH`

从标准输入读取代码，并将处理后的代码写入标准输出。

Biome 使用 `PATH` 选择设置，并根据其扩展名确定输入类型。虚拟路径无需实际存在，也无需属于该项目。它们会绕过 `files.includes` 和 VCS 忽略检查。

```shell
echo 'let a;' | biome check --stdin-file-path=file.js --write
```

#### `--staged`

仅检查已暂存的文件。该选项适用于本地使用。

#### `--changed`

仅检查相对于配置的 `vcs.defaultBranch` 或 `--since` 指定的基础引用存在已提交更改的文件。不包含已暂存和未暂存的更改。该选项适用于 CI。

#### `--since=REF`

设置 `--changed` 使用的基础引用，覆盖 `vcs.defaultBranch`。需要配合 `--changed` 使用。

```shell
biome check --changed --since=main
```

#### `--only=<GROUP|RULE|DOMAIN|ACTION|PLUGIN>`

仅运行指定的 Lint 规则、Assist 辅助操作、规则与操作分组或规则域（domain）。若所选规则的严重性等级为 `off`，Biome 会将推荐规则设置为 `error`，其他规则设置为 `warn`。`plugin` 分组仅运行分析器插件。

```shell
biome check --only=correctness/noUnusedVariables --only=suspicious --only=test --only=plugin
```

#### `--skip=<GROUP|RULE|DOMAIN|ACTION|PLUGIN>`

跳过指定的 Lint 规则、Assist 辅助操作、规则与操作分组或规则域（domain）。匹配的 Lint 规则会被设置为 `off`。该选项优先于 `--only`。`plugin` 分组会跳过分析器插件。

```shell
biome check --skip=correctness/noUnusedVariables --skip=suspicious --skip=project --skip=plugin
```

#### `--watch`

初次运行后，监视所选路径，并重新处理之后修改的文件。

## `biome lint`

对指定文件运行 Linter。

可选的 `PATH` 参数接受一个或多个文件或目录路径。若省略，Biome 会 Lint 当前工作目录中的文件。

```shell
biome lint ./src
```

该命令还接受[全局选项](#global-flags)、相关的[共享选项](#shared-flags)，以及以下附加选项：

<h3>选项</h3>

#### `--write`, `--fix`

应用安全 Lint 修复。

#### `--unsafe`

允许 `--write` 或 `--fix` 应用不安全 Lint 修复。

#### `--suppress`

针对违反 Lint 规则的问题写入抑制注释，而不是应用规则修复。

#### `--reason=STRING`

为 `--suppress` 创建的抑制添加说明。该选项要求同时使用 `--suppress`。

```shell
biome lint --suppress --reason="explanation"
```

#### `--only=<GROUP|RULE|DOMAIN|PLUGIN>`

仅运行指定的 Lint 规则、规则分组或规则域（domain）。若规则的严重性等级为 `off`，Biome 会将推荐规则设置为 `error`，其他规则设置为 `warn`。`plugin` 分组仅运行分析器插件。

```shell
biome lint --only=correctness/noUnusedVariables --only=suspicious --only=test --only=plugin
```

#### `--skip=<GROUP|RULE|DOMAIN|PLUGIN>`

跳过指定的 Lint 规则、规则分组或规则域（domain），将受影响的规则设置为 `off`。该选项优先于 `--only`。`plugin` 分组会跳过分析器插件。

```shell
biome lint --skip=correctness/noUnusedVariables --skip=suspicious --skip=project --skip=plugin
```

#### `--stdin-file-path=PATH`

从标准输入读取代码，并将处理后的代码写入标准输出。

Biome 使用 `PATH` 选择设置，并根据其扩展名确定输入类型。虚拟路径无需实际存在，也无需属于该项目。它们会绕过 `files.includes` 和 VCS 忽略检查。

```shell

```

#### `--staged`

仅 Lint 已暂存的文件。该选项适用于本地使用。

#### `--changed`

仅 Lint 相对于配置的 `vcs.defaultBranch` 或 `--since` 指定的基础引用存在已提交更改的文件。不包含已暂存和未暂存的更改。该选项适用于 CI。

设置 `--changed` 使用的基础引用，覆盖 `vcs.defaultBranch`。需要配合 `--changed` 使用。


#### `--profile-rules`

报告每条规则的运行耗时。不包括准备分析所花费的时间，例如构建语义模型的时间。

#### `--watch`

## `biome migrate`

预览破坏性变更所要求的配置更新。`prettier` 和 `eslint` 子命令则用于从这些工具导入设置。

默认情况下，该命令会显示建议的更改而不修改文件。使用 `--write` 可应用这些更改。

该命令还接受[全局选项](#global-flags)、相关的[共享选项](#shared-flags)，以及以下附加选项：

<h3>选项</h3>

#### `--write`, `--fix`

应用建议的迁移或导入的设置。

<h3>子命令</h3>

#### `biome migrate prettier`

将 Prettier 配置和忽略设置导入 Biome 配置。

#### `biome migrate eslint`

从当前工作目录导入 ESLint 配置和忽略设置到 Biome 配置。

`eslint` 子命令接受这些附加选项：

##### 选项

###### `--include-inspired`

在迁移中包含受 ESLint 规则启发的 Biome 规则。

## `biome search`

实验性功能：查找匹配 [GritQL 模式](https://docs.grit.io/language/patterns) 的代码，可选择限制为特定文件或目录。

必需的 `PATTERN` 参数是要查找的 GritQL 查询。不支持重写查询，因为 `biome search` 是只读的。

<Aside type="tip">

当 shell 支持时，将查询放在单引号内。这样可以防止 shell 将 GritQL 的反引号解释为命令。

</Aside>

可选的 `PATH` 参数将搜索限制为一个或多个文件或目录。未提供路径时，Biome 会搜索当前工作目录中的文件。

以下命令在 `./src` 中查找 `console.log` 调用：

```shell
biome search '`console.log($message)`' ./src
```

该命令还接受[全局选项](#global-flags)、相关的[共享选项](#shared-flags)，以及以下附加选项：

<h3>选项</h3>

#### `-l`, `--language=<css|javascript|json>`

选择用于该模式和被搜索代码的语言语法：CSS、JavaScript 或 JSON。

GritQL 模式针对其目标语法编写，因此一次搜索不能同时针对多种语言。

默认为 `javascript`。

```shell
biome search --language=javascript '`console.log($message)`'
```

## 全局选项

这些选项可用于许多命令，控制整体的 CLI 行为、诊断信息和输出。

<h3 id="general-flags">通用选项</h3>

#### `-h`, `--help`

打印帮助信息。

#### `-V`, `--version`

打印版本信息。

#### `--colors=<off|force>`

控制 ANSI 样式：`off` 禁用它，`force` 即使输出看似不支持 ANSI 转义也强制启用。

#### `--use-server`

连接到正在运行的 Biome 守护进程服务器实例。

#### `--verbose`

显示额外的诊断详情，并列出已处理或已修改的文件。

#### `--config-path=PATH`

设置配置文件的路径，或 Biome 应在其中查找 `biome.json` 或 `biome.jsonc` 的目录。此选项会禁用默认配置文件解析。

使用 **`BIOME_CONFIG_PATH`** 环境变量。

#### `--max-diagnostics=<none|NUMBER>`

限制显示的诊断信息数量。使用 `none` 可取消限制。

默认为 `20`。

#### `--skip-parse-errors`

跳过包含语法错误的文件，而不是发出错误诊断信息。

#### `--no-errors-on-unmatched`

当没有文件被处理时不发出错误。

#### `--error-on-warnings`

如果发出任何警告级诊断信息，则以错误状态退出。

#### `--diagnostic-level=<info|warn|error>`

设置要显示的最低诊断严重性等级：`info`、`warn` 或 `error`。例如，`--diagnostic-level=error` 只显示错误级诊断信息。

默认为 `info`。

<h3 id="reporter-flags">报告器选项</h3>

#### `--reporter=FORMAT`

更改诊断信息和运行摘要的写入方式。

默认为 `default`。

```shell
biome ci --reporter=github
```

| 值 | 输出 |
| --- | --- |
| `default` | 完整的诊断信息和用于终端的摘要。 |
| `concise` | 每条诊断信息一行，格式化器诊断信息归为一组。 |
| `summary` | 按类别和规则分组的诊断信息，以及按文件分组的格式化器诊断信息。 |
| `json` | 机器可读的 JSON。 |
| `json-pretty` | 使用 Biome 默认 JSON 格式化设置美化输出的 JSON。 |
| `github` | 用于创建批注的 [GitHub 工作流命令](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands)。 |
| `gitlab` | 一份 [GitLab 代码质量报告](https://docs.gitlab.com/ci/testing/code_quality/#implement-a-custom-tool)。 |
| `junit` | 用于测试和持续集成（CI）集成的 JUnit XML。 |
| `checkstyle` | [Checkstyle XML](https://checkstyle.org/)。 |
| `rdjson` | [Reviewdog 诊断 JSON](https://deepwiki.com/reviewdog/reviewdog/3.2-reviewdog-diagnostic-format)。 |
| `sarif` | 用于静态分析集成的 [SARIF](https://sarifweb.azurewebsites.net/)。 |

<Aside type="caution">

`json` 和 `json-pretty` 报告器属于实验性功能，可能在补丁版本中发生变更。

</Aside>

#### `--reporter-file=PATH`

将关联报告器的输出写入 `PATH`。未指定 `--reporter` 时，写入默认报告器的输出。

```shell
biome ci --reporter=junit --reporter-file=report.xml
```

重复使用 `--reporter` 可生成多个输出。此示例将默认输出打印到终端，并把 RDJSON 报告写入文件：

```shell
biome ci --reporter=default --reporter=rdjson --reporter-file=report.json
```

### 日志选项

#### `--log-file=PATH`

对于文件处理命令，将 CLI 内部日志写入此文件，而不是标准输出。

使用 **`BIOME_LOG_FILE`** 环境变量。

#### `--log-prefix-name=STRING`

启动守护进程服务器时，设置轮转日志文件使用的文件名前缀。

使用 **`BIOME_LOG_PREFIX_NAME`** 环境变量。

默认为 `server.log`。

#### `--log-path=PATH`

启动守护进程服务器时，设置存储日志文件的目录。

使用 **`BIOME_LOG_PATH`** 环境变量。

默认为 Biome 平台专用缓存目录内的 `biome-logs` 目录。

#### `--log-level=<none|tracing|debug|info|warn|error>`

对于文件处理命令，将 CLI 内部日志级别设置为 `tracing`、`debug`、`info`、`warn`、`error` 或 `none`。

使用 **`BIOME_LOG_LEVEL`** 环境变量。

默认为 `none`。

#### `--log-kind=<pretty|compact|json>`

对于文件处理命令，选择 CLI 内部日志格式：`pretty`、`compact` 或 `json`。

使用 **`BIOME_LOG_KIND`** 环境变量。

默认为 `pretty`。
